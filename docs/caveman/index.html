Agent Skill Explainer

Caveman Skill

AI 에이전트 답변을 짧고 선명한 업무 신호로 압축하는 커뮤니케이션 스킬.

처음 보는 사람을 위한 핵심

AI가 장황하게 말할 때 쓰는 답변 압축 모드 코드, 에러, 경로 같은 기술 정보는 그대로 유지 반복 업무에서 결론과 다음 행동을 빠르게 확인

01. Problem

AI 답변은 기본적으로 길다

처음 배울 때는 친절한 설명이 좋지만, 반복 작업에서는 긴 말이 업무 속도를 늦춘다.

반복해서 보게 되는 문장 물론입니다. 이 문제를 해결하기 위해서는 먼저 가능한 원인을 살펴보고...
실제 필요한 정보 무엇이 문제인가? 어디를 고치나? 어떻게 검증하나?

02. Definition

Caveman은 말투 장난이 아니다

1 출력 형식 규칙 에이전트가 답변할 때 어떤 말을 버리고 어떤 정보를 남길지 정한다.
2 반복 업무 최적화 매번 긴 설명을 읽지 않고 결론, 원인, 조치만 빠르게 본다.
3 정확도 유지 기술 용어, 코드 블록, 에러 메시지는 줄이지 않고 그대로 둔다.

03. Mental Model

에이전트 답변의 마지막 필터

A 사용자 요청 버그 설명, 리뷰 요청, 테스트 실패 로그
B 에이전트 판단 원인 추정, 수정 방향, 검증 방법 정리
C Caveman 필터 예의 문구, 반복 표현, 장황한 연결어 제거
D 압축 답변 문제 -> 원인 -> 조치 -> 검증

04. Rules

버릴 것과 남길 것

핵심은 짧게 말하는 것이 아니라, 정보 밀도를 높이는 것이다.

버린다
물론입니다, 좋은 질문입니다 기본적으로, 실제로, 간단히 말해 확실하지 않지만 아마도 같은 완충어 같은 의미를 반복하는 문장
남긴다
파일명, 함수명, 라인 번호 에러 메시지 원문 명령어와 코드 블록 원인, 영향, 다음 행동

05. Example

같은 내용, 다른 밀도

Caveman은 정보를 삭제하지 않는다. 포장을 줄인다.

일반 답변 이 문제는 인증 미들웨어에서 토큰 만료 시간을 비교하는 조건이 잘못되어 발생한 것으로 보입니다. 현재 코드에서는 만료 시점과 현재 시각이 같은 경우를 처리하지 못하므로 조건을 수정해야 합니다.
Caveman 답변 Auth middleware bug. Expiry check use < not <=. Fix condition. Add boundary test.

06. Bug Triage

오류 분석 예시

터미널 로그를 붙였을 때는 원인과 검증 명령이 바로 보여야 한다.

Error: DATABASE_URL is not defined

Root cause: deploy secret missing.
Impact: app boot fail before DB connect.
Fix: add DATABASE_URL in hosting env.
Verify: restart app, run health check.

07. Code Review

코드 리뷰 예시

리뷰는 친절한 문장보다 위치, 위험, 수정 방향이 더 중요하다.

Caveman 리뷰 L42: user null 가능. guard 필요. L88: retry 무한 루프 위험. max attempt 추가. L130: prod config default 없음 -> deploy crash 가능.
좋은 이유 파일을 다시 열기 전에 무엇을 고쳐야 하는지 바로 보인다.

08. Status Update

상태 보고 예시

작업 중간 보고는 길수록 읽히지 않는다. 완료, 막힘, 다음만 있으면 된다.

Done: README update, Pages enabled.
Verified: link 200 OK, slide nav works.
Blocked: none.
Next: review wording, then add next skill deck.

09. How To Use

어떻게 켜고 끄나

스킬은 보통 사용자의 짧은 신호로 켜진다. 한 번 켜지면 명시적으로 끌 때까지 유지된다.

켜기 `$caveman`, `caveman mode`, `less tokens`, `be brief`
유지 다음 답변부터 계속 압축 모드. 매번 다시 말할 필요 없음.
끄기 `stop caveman`, `normal mode`, `자세히 설명해줘`

10. Safety

항상 짧으면 위험하다

좋은 스킬은 예외 규칙을 가진다. 오해 비용이 큰 순간에는 압축을 풀어야 한다.

압축 풀기
삭제, 결제, 권한 변경 같은 되돌리기 어려운 작업 보안/법무/개인정보 관련 안내 처음 배우는 사람에게 개념을 설명하는 상황
다시 압축
위험 설명과 확인이 끝난 뒤 사용자가 다시 짧게 말하라고 했을 때 반복 작업 상태 보고로 돌아왔을 때

11. Use Case Matrix

언제 쓰면 좋은가

✓ 코드 리뷰 문제 위치와 수정 방향 중심.
✓ CI 실패 실패 원인, 영향, 재실행 명령 중심.
! 초보자 교육 너무 짧으면 배경 이해가 끊김.
! 고객 문안 친절함과 맥락 설명이 필요.

12. Practical Recipe

팀에서 쓸 때의 요청문

처음부터 “짧게”만 말하지 말고 출력 구조를 같이 지정하면 품질이 안정된다.

Use caveman mode for this task.
Format:
1. Root cause
2. Risk
3. Fix
4. Verify command

Keep exact error text and file paths.

13. Skill Design Lesson

좋은 스킬은 작고 선명하다

Caveman이 좋은 이유는 기능이 많아서가 아니라, 하나의 반복 문제를 확실히 해결하기 때문이다.

1 좁은 목적 답변 압축이라는 한 가지 일에 집중.
2 명확한 예시 나쁜 답변과 좋은 답변의 차이가 바로 보임.
3 예외 규칙 위험한 순간에는 짧게 말하지 않도록 제한.

14. Takeaway

핵심은 “짧게”가 아니라 “신호만 남기기”

Caveman은 AI를 무뚝뚝하게 만드는 스킬이 아니다. 반복 업무에서 사람이 빨리 판단할 수 있게 답변을 업무용 신호로 바꾸는 스킬이다.

한 문장 요약

Caveman = 반복 작업용 출력 압축 전략. 결론, 원인, 조치, 검증만 남긴다.
