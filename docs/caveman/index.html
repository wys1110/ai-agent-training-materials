Caveman Skill

Claude가 너무 길게 말하나요?

단순한 질문에도 서론·예의 표현·완충어가 잔뜩 붙어 나온다면, Caveman이 필요한 순간이다.

이 자료에서 다루는 것

왜 이 스킬이 필요한가 — 어떤 불편을 해결하는가 켜면 뭐가 달라지는가 — 실제 before/after 언제 쓰면 좋은가 — 구체적인 상황 안전한가 — 위험할 때 어떻게 동작하는가

문제 · 이 상황, 공감되나요

디버깅 중인데 블로그 포스트가 날아온다

에러 메시지 하나 물어봤을 뿐인데, 서론→배경→가능한 원인→결론 순으로 답변이 온다. 원하는 건 단 한 줄이었는데.

문제 · 이럴 때 특히 답답하다

짧게 받아야 할 순간들

1 디버깅 중 에러 원인과 수정 방향만 필요한데 긴 설명이 따라온다.
2 코드 리뷰 코멘트 하나에 "훌륭한 질문입니다" 같은 서론이 붙는다.
3 빠른 확인 API 파라미터 하나 확인하려는데 전체 사용 방법이 나온다.
4 반복 질문 같은 패턴의 질문을 여러 번 할 때 매번 긴 답변을 읽어야 한다.

효과 · 이 스킬이 바꾸는 것

토큰 75% 감소. 정보 손실 없음.

군더더기·서론·예의 표현을 제거하되, 기술 용어·코드·에러 메시지는 그대로 남긴다. 짧아지되 내용은 유지된다.

~75% 토큰 감소 — 같은 정보를 4배 빠르게 읽을 수 있다
줄어드는 것 관사, filler(just/really/basically), 예의 문구(Sure!/Of course!), 완충 표현
남는 것 기술 용어, 코드 블록, 에러 메시지, 파일 경로 — 중요한 건 빠지지 않는다

효과 · 실제 비교

같은 답변, 다른 밀도

정보는 동일하다. 읽는 시간만 줄어든다.

Before (일반 모드)
Sure! I'd be happy to help. The issue you're experiencing
with your React component re-rendering is likely caused by
the fact that you're passing an inline object as a prop,
which creates a new reference on every render. You might
want to consider using the useMemo hook to address this.
After (Caveman 모드)
Inline obj prop → new ref → re-render. useMemo.

사용법 · 이렇게 켠다

말 한 마디면 된다

스킬 파일에 등록된 트리거 표현 중 하나를 말하면 즉시 활성화된다. 설정 변경이나 재시작 없이.

영어 트리거 "caveman mode" / "talk like caveman" / "be brief" / "less tokens" / /caveman
한국어 트리거 "짧게" / "토큰 줄여" / "간단히" / "caveman 모드"
끄는 방법 "stop caveman" / "normal mode" / "자세히 설명해줘"

사용법 · 한 번 켜면 유지된다

끄기 전까지 모든 응답에 적용

매 질문마다 "짧게 말해줘"를 반복할 필요 없다. 한 번 켜면 대화가 끝날 때까지 유지된다.

이런 걱정은 안 해도 된다

몇 턴 지나면 다시 길어지지 않나? — No. 명시적으로 끄기 전까지 흔들리지 않는다. 복잡한 질문하면 자동으로 풀리지 않나? — No. 여전히 caveman 모드다. 도중에 켜도 되나? — Yes. 대화 중간에 언제든 켜고 끌 수 있다.

사용법 · 이럴 때 효과적이다

Caveman이 빛나는 상황

✓ 반복 디버깅 같은 코드베이스에서 에러를 계속 잡을 때. 긴 답변을 읽을 여유가 없다.
✓ 빠른 API 확인 파라미터·타입·반환값만 필요할 때. 배경 설명은 필요 없다.
✓ 코드 리뷰 코멘트 여러 줄 코드에 대해 짧고 정확한 피드백을 받고 싶을 때.
✓ 토큰 절약 긴 컨텍스트를 유지하면서 응답 길이를 줄여야 할 때.

안전망 · 위험할 때는 자동으로 상세해진다

짧게 말하다 실수할 수 있는 순간은 따로 처리한다

보안 경고·되돌릴 수 없는 작업·복잡한 순서는 caveman을 잠깐 벗어나 명확하게 경고한다. 완료 후 자동으로 돌아온다.

위험 작업 예시:

> **Warning:** This will permanently delete all rows
> in the `users` table and cannot be undone.
>
> ```sql
> DROP TABLE users;
> ```
>
> Verify backup exists first.

Caveman resume. Next.

안전망 · 이 상황에서는 자동으로 자세해진다

짧게 말하면 안 되는 4가지 순간

! 보안 경고 보안 취약점·인증 문제는 절대 짧게 처리하지 않는다.
! 되돌릴 수 없는 작업 DROP, DELETE, 파일 삭제 등은 명확한 확인을 요구한다.
! 순서가 중요한 절차 단계 순서를 잘못 이해하면 문제가 생기는 작업.
! 반복 질문 같은 질문을 반복하면 이해가 안 됐다는 신호. 상세 설명으로 전환.

사용법 · 실제 답변 예시

이런 식으로 나온다

코딩 대화 전반에서 같은 밀도로 적용된다.

"DB connection pooling이 뭐야?"
Pool = reuse DB conn. Skip handshake → fast under load.

"왜 React 컴포넌트가 자꾸 리렌더되지?"
Inline obj prop → new ref every render → re-render.
Fix: useMemo or move obj outside component.

"auth 미들웨어 토큰 검증 버그야?"
expiry check: `<` not `<=`. Off-by-one. Fix line 42.

정리 · 지금 바로 써보세요
