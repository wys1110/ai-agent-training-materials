Caveman

AI 답변을 더 짧고 빠르게. 기술 정보는 그대로, 군더더기만 제거한다.

오늘 다룰 것

Caveman이 뭔지, 왜 쓰는지 트리거 방법과 실제 답변 차이 안전 장치와 지속성 설치 방법과 팀 활용 시나리오

01. 문제

AI 답변, 꼭 이렇게 길어야 할까?

실제 정보보다 서론·인사·완충 표현이 더 많다. 읽는 시간과 토큰이 낭비된다.

일반 모드 — 실제 정보는 절반도 안 된다

물론입니다! 도움을 드리게 되어 정말 기쁩니다.
말씀하신 문제를 해결하기 위해, 우선 가능한
원인을 분석해 보겠습니다. 기본적으로 이 오류는
여러 상황에서 발생할 수 있는데, 가장 흔한
경우는 설정 값이 잘못 지정된 경우입니다...

↑ 실제 정보에 도달하기 전에 이미 지쳐있다

02. Caveman

기술 정보는 그대로, 군더더기만 삭제

Claude Code에서 바로 쓸 수 있는 스킬. 한 마디로 켜고, 꺼질 때까지 계속 유지된다.

↓ ~75% 토큰 절감 군더더기·관사·인사말 제거
✓ 기술 정확도 유지 코드·에러·용어는 손대지 않음
⚡ 켜고 끄기 간단 말 한마디로 on/off

03. 켜는 방법

말 한마디로 켠다

아래 표현 중 하나를 채팅에 입력하면 즉시 활성화된다.

켜기 ”caveman mode”  ·  “talk like caveman”  ·  “use caveman”  ·  “less tokens”  ·  “be brief”  ·  /caveman
끄기 ”stop caveman”  ·  “normal mode”  ·  “자세히 설명해줘”

04. 실제 비교

”왜 React 컴포넌트가 리렌더링 돼?”

일반 모드

안녕하세요! React 컴포넌트가 불필요하게
리렌더링되는 문제는 상당히 자주 발생하는
현상입니다. 기본적으로 React는 상태나 props가
변경될 때 컴포넌트를 리렌더링하는데, 객체를
inline으로 생성하면 매 렌더마다 새로운 참조가
생성되기 때문에 변경으로 인식합니다.
이를 해결하는 방법으로는 useMemo 훅을
사용하시는 것을 권장드립니다.
Caveman 모드

Inline obj prop → new ref → re-render.
`useMemo`.

05. 유지되는 것

기술 정보는 손대지 않는다

압축 모드라도 실무에서 중요한 정보는 절대 줄이지 않는다.

✓ 유지 기술 용어 · 코드 블록 · 에러 메시지 · 파일 경로 · 정확한 수치
✗ 삭제 관사(a/an/the) · 인사말 · 완충 표현 · 장황한 설명 · 불필요한 확인 
패턴: [대상] [동작] [이유]. [다음 조치].

06. 안전 장치

위험한 순간엔 자동으로 자세해진다

보안 경고·되돌릴 수 없는 작업에서는 잠깐 일반 모드로 전환 후 다시 Caveman으로 돌아온다.

사용자: “users 테이블 전부 지워줘”

⚠ Warning: This will permanently delete all rows
in the `users` table and cannot be undone.

```sql
DROP TABLE users;
```

Caveman resume. Verify backup exist first.

07. 지속성

한 번 켜면 계속 유지된다

1 켜질 때 트리거 표현을 말하는 순간부터 즉시 적용
2 유지 기간 명시적으로 끄기 전까지 모든 답변에 적용
3 흔들림 없음 여러 턴이 지나도 장황한 말투로 돌아가지 않음
4 끄기 ”stop caveman” 또는 “normal mode”로 즉시 종료
