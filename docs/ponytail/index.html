Skill Markdown Explainer

Ponytail SKILL.md

느슨하고 비효율적인 코드를 단단한 묶음으로 당기는 최적화 스킬의 구조를 이해한다.

이번 자료의 방향

추상 설명보다 실제 markdown 원문을 먼저 본다. 최적화 스킬이 왜 우선순위와 guardrail이 중요한지 이해한다. 다른 최적화 스킬에도 재사용할 형식을 뽑아낸다.

목차 · 이렇게 진행한다

4개 챕터로 나눠 본다

1 원문 실제 SKILL.md 전체를 먼저 읽는다. 분석 전에 전체 맥락을 잡는다.
2 구조 Frontmatter, Core Rule, Persistence, Rules, Guardrails 각 블록의 역할을 해설한다.
3 예시 N+1 쿼리 같은 실제 before/after 코드 쌍과 예외 상황을 본다.
4 재사용 구조를 뽑아내고 다른 최적화 스킬을 만들 때 쓸 템플릿으로 정리한다.

원문 · 실제 Markdown

스킬은 Markdown 파일 하나로 시작한다

처음 `---` 블록은 메타데이터다. 에이전트가 이 스킬을 언제 불러야 하는지 판단하는 힌트가 된다.

---
name: ponytail
description: >
  Code optimization mode. Scans for performance
  bottlenecks, redundant operations, and inefficient
  patterns, then applies targeted fixes while preserving
  exact behavior and public interfaces.
  Use when user says "optimize", "make it faster",
  "ponytail", "코드 최적화", "성능 개선",
  or invokes /ponytail.
---

Pull scattered, slow code into a tight, efficient bundle.
Identify the highest-impact bottleneck first.
Fix, measure, repeat.
Never change observable behavior.

구조 · Frontmatter

`name`과 `description`이 입구다

description에 트리거 상황이 구체적으로 있어야 에이전트가 정확히 고른다. 영어와 한국어 트리거를 모두 넣으면 다국어 대화에서도 발동한다.

`name: ponytail` 사람이 부르는 짧은 이름. 링크나 목록에서 식별하는 역할.
`description` "make it faster", "코드 최적화", "성능 개선"처럼 실제 사용자 표현을 포함시킨다.
다국어 트리거의 이점 영어+한국어 표현을 모두 넣으면 대화 언어와 관계없이 스킬이 발동한다.

구조 · Core Rule

첫 세 문장이 스킬의 기준선이다

목표·전략·금지선이 각 한 줄. 이 세 줄이 없으면 모든 코드를 무차별 변경할 위험이 있다.

Pull scattered, slow code into a tight, efficient bundle.
Identify the highest-impact bottleneck first.
Fix, measure, repeat.
Never change observable behavior.

세 줄의 역할

Pull into tight bundle — 최적화 방향 고정. highest-impact first — 전략: 가장 큰 병목부터. Never change behavior — 불변 조건: 동작 변경 금지.

구조 · Persistence

이 스킬은 작업 단위로 적용된다

Caveman처럼 대화 전체가 아니라, 현재 작업 단위로 범위를 좁혔다. 그래야 최적화가 남발되지 않는다.

## Persistence

ACTIVE FOR THE CURRENT TASK once triggered.
Apply to every code block shown unless
  user says "skip this one".
Off when user says "done" or "stop ponytail".
1 언제 켜짐 최적화 관련 표현을 말하면 즉시 활성화.
2 적용 범위 현재 작업의 모든 코드 블록에 적용.
3 건너뛰기 "skip this one"으로 특정 블록 제외 가능.
4 종료 조건 "done" 또는 "stop ponytail"이 off 신호.

구조 · Rules — 최적화 대상

무엇을 최적화할지 우선순위로 정한다

"빠르게 만들어"보다 강한 이유는 대상이 우선순위별로 구체화되어 있기 때문이다.

## Rules

Targets (in priority order):
- O(n²)+ loops → reduce complexity
- Repeated expensive calls inside loops
    → hoist or cache
- Unnecessary allocations
    → reuse or preallocate
- N+1 DB queries → batch or join
- Redundant recomputation → memoize
- Dead code paths → remove

구조 · Guardrails — 지킬 것

바꾸면 안 되는 것도 정한다

최적화 스킬의 핵심은 속도가 아니라 안전성이다. 동작을 바꾸지 않고 빠르게만 만들어야 한다.

Keep: all observable behavior,
      public API signatures, error handling.

Show: before snippet, after snippet,
      one-line reason per change.

Order changes by impact (biggest win first).
No refactors beyond the optimization boundary.
Targets / Keep 구분이 핵심이다 무엇을 바꿀지와 무엇을 지킬지를 동시에 정의해야 잘못된 최적화를 막는다.

구조 · Output Pattern

형식이 있으면 변경 사유가 명확해진다

1 Location 어디를 바꿨는지 먼저 말한다. 함수명이나 파일:라인.
2 Problem 어떤 비효율이 있었는지 말한다. N+1, O(n²) 등.
3 Fix 어떻게 고쳤는지 말한다. JOIN, 캐시, 메모이제이션 등.
4 Reason 왜 더 빠른지 한 줄로 붙인다. n회 왕복 → 1회 등.

예시 · Before / After

나쁜 답변과 좋은 답변을 같이 둔다

최적화 스킬은 설명보다 결과가 먼저다. 위치·문제·수정을 한 줄로 먼저 제시한다.

Not:
"This code could be improved in several ways.
First, you might want to consider that the loop
structure here is potentially suboptimal..."

Yes:
"getUsersByTeam — N+1 query → single JOIN query
(eliminates n DB round trips)"

예시 · 실제 코드

고빈도 패턴을 예시로 넣는다

N+1 쿼리는 실무에서 가장 자주 만나는 병목이다. before/after가 같이 있어야 에이전트가 패턴을 배운다.

**"N+1 DB query in getUsersByTeam"**

Before:
for (const team of teams) {
  users.push(
    await db.query(
      'SELECT * FROM users WHERE team_id = ?',
      team.id
    )
  );
}

After:
const users = await db.query(
  'SELECT * FROM users WHERE team_id IN (?)',
  teams.map(t => t.id)
);

예시 · 예외 규칙

예외 규칙이 있어야 실무에서 안전하다

데이터 없이 최적화하면 잘못된 곳을 손댄다. 동작을 바꾸는 수정은 최적화가 아니다.

## Exceptions

Do NOT optimize when:
- no profiling data shows this is actually slow
    (premature optimization),
- the fix changes observable output or error behavior,
- the change requires a library upgrade
    (flag only, do not apply),
- the code is a test fixture or
    intentionally readable demo.

Flag these and explain why,
then resume on the next target.

예시 · 조기 최적화

데이터 없이 최적화하면 멈추고 경고한다

성능 문제가 확인되지 않은 코드는 그대로 두는 것이 최적화다.

Example -- premature optimization:

> **Skip:** No profiling data confirms this loop
> is a bottleneck.
> Current avg. response time: < 2 ms.
>
> Optimizing here risks readability loss
> with no measurable gain.
> Run a profiler first, then re-invoke /ponytail.
>
> Ponytail resume.
> Next target: getUsersByTeam N+1 query.

재사용 · 구조 정리

Ponytail에서 뽑는 스킬 작성 형식

A Metadata name, description, trigger phrases (영어+한국어).
B Core Rule 목표·전략·금지선을 3줄로 고정.
C Operating Rules 우선순위 목록, guardrail, 출력 형식.
D Examples before/after 코드 쌍, 예외 상황과 경고 문구.

재사용 · 템플릿

다른 스킬도 이 뼈대로 시작한다

Ponytail 형식은 특정 분야 최적화 스킬을 만들 때 재사용하기 좋다.

---
name: short-skill-name
description: >
  What this skill does.
  Use when user says X, asks for Y, or needs Z.
---

Core behavior: goal, strategy, constraint.

## Persistence
When active, scope, how to skip, how to stop.

## Rules
Targets in priority order.
What to keep unchanged. Output format.

## Examples
Not: ...  Yes: ...

## Exceptions
When to pause, flag, or skip entirely.

재사용 · 한국어 버전

한글로 옮기면 이런 코드가 된다

구조는 동일하다. 트리거 표현과 대상 목록만 한국어로 바꾸면 된다.

---
name: ponytail-ko
description: >
  코드 최적화 모드. 성능 병목, 중복 연산, 비효율 패턴을 찾아 수정한다.
  동작과 공개 API는 그대로 유지한다.
  사용자가 "최적화", "빠르게", "ponytail", "코드 정리",
  "성능 개선", "/ponytail"처럼 말할 때 사용한다.
---

느슨한 코드를 단단한 묶음으로 당긴다.
가장 큰 병목부터 찾는다. 고치고, 확인하고, 반복한다.
동작은 절대 바꾸지 않는다.

## 상태 유지
현재 작업에만 적용한다.
"이건 건너뛰어"라고 하면 해당 블록은 제외한다.
"완료" 또는 "ponytail 그만"이라고 하면 끈다.

## 규칙
대상 (우선순위 순):
- O(n²)+ 루프 → 복잡도 낮추기
- 루프 안 반복 호출 → 호이스트 또는 캐시
- 불필요한 할당 → 재사용 또는 사전 할당
- N+1 DB 쿼리 → 배치 또는 JOIN
- 중복 연산 → 메모이제이션
- 사용하지 않는 코드 경로 → 제거

유지: 동작, 공개 API, 에러 처리.
표시: 변경 전, 변경 후, 이유 한 줄.

재사용 · 핵심 정리

좋은 최적화 스킬은 안전망이 있다

Ponytail의 강점은 빠르게 만드는 것이 아니라, 우선순위·guardrail·예외가 명확해서 잘못된 최적화를 막는다는 점이다.

한 문장 요약

최적화 스킬은 "빠르게 해줘"가 아니라, 무엇을 먼저·어디까지·언제 멈출지를 규정한 markdown 규격이다.
